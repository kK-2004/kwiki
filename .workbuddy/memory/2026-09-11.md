# 2026-09-11

## 调研：kk-common 的 redis / redisson 开关改为 true 需要哪些配置变更

对 `kk-common:0.1.2` 工件做字节码级核实（`~/.m2/.../kk-common-0.1.2.jar`）：

- `RedissonLockAutoConfiguration.redissonClient` 仅用 Spring Boot `RedisProperties` 的
  **host / port / database / password(hasText 才 set) / timeout** 构造
  `Config.useSingleServer().setAddress("redis://host:port")`。因此
  `spring.data.redis.url`、`ssl.enabled`、`username`(ACL)、sentinel/cluster 一律不生效；
  需要 TLS/ACL/集群时必须自建 `RedissonClient` Bean（SDK `@ConditionalOnMissingBean` 会让位）。
- 建连时机不同：`redis=true` 只引入 Lettuce 连接工厂（懒建连）；`redisson=true` 走
  `Redisson.create()`（Redisson `lazyInitialization` 默认 false）→ 启动期即建连，Redis 不可达就启动失败。
- `redis=true` 时 Boot 的 `RedisHealthContributorAutoConfiguration`
  （`@ConditionalOnBean(RedisConnectionFactory.class)`）会额外注册 Spring 自带的 `redis` 健康指示器，
  与 `KwikiRedisConfiguration` 的 `kwikiRedisHealthIndicator` 并存，两者都命中
  `management.endpoint.health.group.readiness.include: "readinessState,*"`。
- `KWIKI_REDIS_HOST` 在两个 yml 中都是无默认值的占位符 → 任一开关开启后即成为启动硬依赖。
- redisson 3.37.0 由 kk-common 以 compile 作用域传递，已在 classpath，pom 无需改动。
- 结论：开关只需改环境变量；不要把 application.yml 里 `:false` 的字面默认值改成 true，
  否则 `@SpringBootTest` 会去解析 `spring.data.redis.host` 而抛占位符无法解析。
