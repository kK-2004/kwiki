## Context

kwiki 的附件上传已经通过 `AttachmentStorage` 接入 kFile 内容中心，数据库中的 `Attachment.contentCenterFileId` 是附件唯一持久内容标识；存储适配器能够按该 id 读取字节、生成下载链接或 CDN 链接。索引任务读取原始附件后交给 `DocumentParseService`，PDF 当前由 Tika 仅抽取正文，`TikaStructParser` 明确关闭内嵌媒体解析。

Markdown 页面在发布事务中保存修订、扫描媒体引用并异步排入 PAGE 索引任务。手动上传图片使用 `attachment://uuid`，已有 `page_revision_media` 可关联到 `Attachment.contentCenterFileId`；HTTP(S) 外链图片当前只展示且明确不抓取。`MarkdownStructParser` 只组装文本节点，图片源地址和资源身份不会进入 `StructuredDocument`。因此 PDF 图片与已发布 Markdown 的上传/外链图片都不会在 ES 中保留位置、摘要或可回显身份。

本变更跨越 PDF 解析、内容中心、视觉模型、任务幂等、分块和检索结果装配。所有处理必须留在 Java/Spring Boot 进程中；不得调用 MarkItDown、Python 或 FastAPI。视觉模型使用 OpenAI-compatible Chat Completions 协议与 `qwen3.7-flash`，图片输入必须是内容中心 CDN URL。

## Goals / Non-Goals

**Goals:**

- 从 PDF 中提取具有可见绘制位置的图片，并将图片摘要插入与原文一致的位置。
- 在页面发布后的异步索引阶段处理 Markdown 上传图片和 HTTPS 外链图片，在其源码位置生成摘要索引投影，同时保持页面源 Markdown 不变。
- PDF 图片和外链图片先作为派生资源存入 kFile；手动上传图片复用已有内容中心对象；三者都以内容中心 CDN URL 调用视觉模型。
- 使用仅含 `type`、`contentId` 的稳定标记协议保存图片引用，并让摘要参与检索。
- 让受保护块在父子分块中保持原子性，检索后能解析为结构化资源引用。
- 对重试、并发、超时、失败分类、凭据与 URL 脱敏提供明确契约。

**Non-Goals:**

- 不实现扫描版 PDF 的整页 OCR，也不把每页统一渲染为图片送给模型。
- 不处理 DOCX、PPTX、XLSX 或独立 HTML 文档的内嵌图片；首期文档附件只处理 PDF，页面内容额外处理 Markdown 图片语法和其中的 `<img>`。
- 不修改已发布页面的 Markdown，不用摘要块替换页面阅读视图中的原图片语法。
- 不让视觉模型生成正文 OCR 的替代文本；摘要用于补充图片语义。
- 不在标记或 Elasticsearch 中持久化 CDN URL、签名 URL、模型 API Key。
- 不引入 MarkItDown、独立解析微服务或新的 Python 运行时。

## Decisions

### 1. 在 Java 内以 PDFBox 构建带位置的 PDF 多模态解析器

PDF 路径使用项目现有 Tika/PDFBox 依赖体系中的 PDFBox API。解析器逐页收集正文块及图片绘制事件，以页码和页面坐标建立稳定顺序，再组装为 `StructuredDocument`。图片提取以实际绘制事件为准，而不是只枚举 PDF resources；这样可以获得插入位置，并避免把未绘制资源误当正文图片。相同图片字节在同一源文档内按 SHA-256 复用上传与摘要结果，但每个绘制位置仍产生一个标记。

图片蒙版、空内容和低于可配置像素/面积阈值的装饰资源可以跳过，跳过原因计入指标。无法提取正文但包含图片的扫描版 PDF 仍按现有规则拒绝；本能力不是 OCR。

备选方案是继续使用 Tika XHTML 并打开 embedded extraction，但其内嵌资源回调不能可靠表达图片在 PDF 页面正文中的绘制顺序。另一个方案是整页渲染，它会显著增加调用成本并把正文重复送入视觉模型，因此不采用。

### 2. 图片上传到内容中心后再调用视觉模型

解析出的图片先编码为内容中心接受的 PNG 或保留可验证的 JPEG，通过 `AttachmentStorage.store` 上传。上传时 MIME 仍是必要的：内容中心会校验请求与响应类型，视觉服务/CDN 也依赖正确的响应类型；但 MIME 不进入文本标记，因为回显可由 `contentId` 向内容中心获取权威类型或响应头。

为支持任务重试和多索引版本共享中间结果，新增派生资源持久记录，至少关联源附件、源内容 id/版本身份、图片内容哈希、页码/稳定序号、派生图片 `contentId`、摘要状态与摘要文本。唯一约束以源内容身份、解析器版本和图片内容哈希为核心，避免同一次源文档的重试重复上传；同图多位置复用同一个派生 `contentId`。只有完成上传且获得正整数 `contentId` 的记录才可进入标记。

若内容中心当前 SDK 不支持删除，失败上传和被替换源文档产生的资源记录必须保持可审计并进入独立清理队列/指标，不能在索引事务中假装已删除。后续具备删除 API 时由清理任务回收；索引切换期间不得删除仍被任一有效索引引用的资源。

### 3. 发布后的 Markdown 图片使用索引投影，不改源修订

PAGE 索引任务读取已发布修订的原始 Markdown，使用现有 `MarkdownMediaScanner` 的源码区间识别标准 `![alt](src)` 与 `<img src="...">`，跳过代码围栏和转义示例。处理结果只用于 `StructuredDocument`、分块、embedding 和 ES 写入；数据库中的修订 Markdown 继续保留原始图片语法，页面渲染行为不变。

资源解析分两类：

- `attachment://uuid`：在当前知识库和修订媒体引用范围内解析附件，要求附件状态为 STORED、类型为经嗅探确认的图片，并直接复用 `Attachment.contentCenterFileId`。同一内容 id 的摘要按内容哈希、模型和提示词版本复用，不重新上传。
- 外部链接：首期只接受绝对 HTTPS URL。索引 worker 通过专用安全下载器抓取，校验最终地址、响应类型、图片魔数、字节/像素限制和重定向链，然后镜像上传内容中心，后续只使用新 `contentId` 和内容中心 CDN URL；原外链 URL 不进入 ES 标记。

外链抓取改变了当前“外链永不服务端获取”的边界，因此必须实施 SSRF 防护：只允许 HTTPS，禁止 URL user-info 和非标准端口（除非显式白名单），DNS 解析前后拒绝 loopback、link-local、site-local、私网、保留地址及云元数据网段，每次重定向重新校验，限制重定向次数、响应大小、超时和解码像素，并禁止携带用户 cookie、Authorization 或内部请求头。不支持的 scheme、相对地址、data URI 或安全校验失败会使该发布修订的索引任务显式失败，不能悄悄只索引 alt 文本。

图片在 Markdown 中的起止偏移决定保护块位置；周围普通 Markdown 仍由结构解析器生成标题/段落。重复引用同一附件或相同外链内容可复用摘要和 `contentId`，但每个语法位置都生成保护块。

备选方案一是把外链原 URL 直接交给视觉模型，但无法满足保护块必须持有 kFile `contentId` 的回显契约，且模型侧抓取行为不可控。备选方案二是在页面保存/发布事务里同步摘要，会把外部网络和模型延迟引入发布事务；因此选择发布成功后由既有异步索引任务完成。

### 4. 视觉模型使用独立、可配置的 OpenAI-compatible 客户端

新增独立的多模态模型配置，包含 `base-url`、`api-key`、`model`、连接/请求超时、最大重试次数、并发数和提示词版本；模型默认/部署值为 `qwen3.7-flash`。客户端调用 `/chat/completions`，请求核心结构为：

```json
{
  "model": "qwen3.7-flash",
  "messages": [{
    "role": "user",
    "content": [
      {"type": "image_url", "image_url": {"url": "<content-center-cdn-url>"}},
      {"type": "text", "text": "<versioned image-summary prompt>"}
    ]
  }]
}
```

提示词要求输出一段可独立检索的中文事实摘要，描述图片类型、主题、关键文字、实体、数值、趋势和关系；不得输出 Markdown 图片语法、标记协议或臆测不可见信息。客户端只接受非空的 `choices[0].message.content`，对 429、5xx、连接错误和超时执行有界退避重试，对其他 4xx 和响应结构错误判为永久失败。日志、异常和 trace 不记录 API Key、完整 CDN URL 或请求体。

备选方案是复用回答模型配置，但图片摘要有独立模型、并发和超时生命周期，混用会造成凭据和容量耦合，因此采用独立配置与客户端；底层仍可复用现有可取消 HTTP 传输、追踪和脱敏基础设施。

### 5. 定义最小且可严格解析的 `KWIKI_META_DATA` 协议

每个图片位置生成以下规范块，JSON 使用紧凑序列化，`contentId` 为正整数：

```text
<<KWIKI_META_DATA_START {"type":"image","contentId":12345}>>
图片的 LLM 摘要
<<KWIKI_META_DATA_END {"type":"image","contentId":12345}>>
```

START 与 END 的 `type`、`contentId` 必须一致。首期只允许 `type=image`，但保留 `type` 字段以便未来扩展表格、图表或音视频。标记不包含 `mime`、源文档 id、页码、哈希或 URL；这些字段要么只服务内部幂等，要么可通过 `contentId` 解析，不应污染 embedding 文本。

解析器使用 JSON 解析而不是依赖字段顺序的正则表达式，并限制元数据长度、摘要长度和嵌套标记。畸形或不配对标记必须显式失败，不能被当作普通用户文本或可回显资源。普通文档中碰巧出现同名字符串时，只有完整通过协议校验的成对块才具有资源语义。

### 6. 扩展结构化文档与分块，使多模态块原子化

`StructuredDocument` 除正文/标题外表达受保护资源块，组装后的 `plainText` 保留完整标记和摘要。父块与子块分块器将整个块视为不可切分单元：切分点不得落在 START 与 END 之间；当单个块超过常规上限时允许该块独占一个超限 chunk 并记录指标，而不是截断协议。

用于 embedding 和 LLM 检索上下文的文本投影去掉 START/END 包装但保留摘要；用于存储和资源提取的内容保留完整块。索引文档同时写入由块解析得到的去重 `contentIds` 数组，便于可靠装配资源引用，不要求查询时重新扫描所有文本；原始块仍是可重建该字段的事实来源。解析器版本必须升级，以触发已索引文档的显式重建，而不是静默混用旧解析结果。

### 7. 回显只暴露 `contentId` 身份，URL 在请求时解析

检索结果或引用 DTO 返回 `type` 与 `contentId`，可选返回经过当前知识库授权后即时生成的预览/CDN URL。持久聊天记录和 Elasticsearch 不保存 URL。服务端在签发链接前验证当前用户仍有源知识库/文档的读取权限；不得提供一个仅凭任意 `contentId` 即可换取链接的未授权公共接口。

若部署的内容中心 CDN URL 天然公开且长期有效，它仍只作为一次响应字段使用；视觉模型调用也在每次需要时通过 `contentId` 获取新 URL。

### 8. 失败保持索引语义完整，并复用现有任务重试

对带有合格图片的 PDF 或已发布 Markdown，图片解析、外链抓取、上传或摘要任一阶段失败时，本次资源索引不提交不完整的新版本，并让现有 worker 按瞬时/永久分类处理。已完成的派生记录供重试复用，避免重复上传和重复模型调用。纯文本内容或只有被明确过滤的装饰图片不触发视觉模型，按原文本路径完成。

并发索引同一源文档时，通过数据库唯一约束与行状态协调；只有一个执行者创建资源/摘要，其余执行者读取完成结果或进行有界等待。外部调用不能持有长数据库事务。

## Risks / Trade-offs

- [PDF 页面缺少天然阅读顺序，复杂双栏或浮动图片可能排序不理想] → 使用页码和坐标的确定性排序，建立多栏/多图测试语料，并保留解析器版本以便算法升级后重建。
- [PDF 图片可能是矢量绘制或由多个小图层组成] → 首期只保证可提取的栅格图片；记录未覆盖类型，后续可按数据决定是否增加区域渲染。
- [CDN 对模型服务不可达或需要鉴权] → 启动/健康检查验证配置，错误按外部依赖失败暴露；不退回 base64，因为用户要求使用内容中心 CDN URL。
- [多图文档产生较高模型成本和处理延迟] → 按哈希去重、限制并发、配置单文档图片上限并暴露计数与耗时指标；达到上限时显式失败而非静默截断。
- [派生资源上传成功但任务随后失败，可能留下孤儿] → 持久记录上传状态，重试复用，并提供可审计的清理候选；没有安全删除能力时不做猜测性删除。
- [摘要模型输出不稳定影响索引一致性] → 固定模型名、提示词版本和温度等生成参数，将版本纳入派生结果身份；版本变化通过索引重建生效。
- [标记文本被模型或用户内容伪造] → 严格 JSON/配对校验、仅信任索引流水线生成的资源字段，并在链接解析时重新授权。
- [抓取 Markdown 外链图片引入 SSRF、重定向绕过和压缩炸弹风险] → 使用隔离的安全下载器，对初始 URL、DNS 结果及每次重定向重复执行地址策略，限制字节、像素、时间和内容类型，且绝不转发用户凭据。
- [外链图片变化或失效造成摘要漂移] → 首次成功处理后以镜像到内容中心的不可变内容及哈希作为索引身份；新页面修订触发重新解析，失败不覆盖上一成功索引版本。

## Migration Plan

1. 增加派生资源表与视觉模型配置，但默认关闭多模态开关；部署并验证内容中心、外链下载策略与模型连通性。
2. 上线 PDF/Markdown 多模态解析器、标记解析器、原子分块和索引字段，新建 parser 版本并完成自动化测试。
3. 在测试知识库开启功能，发布带上传/外链图片的 Markdown 页面并重建带图 PDF，比较正文 chunk、图片数量、摘要质量、耗时和失败率。
4. 分批开启生产知识库并通过现有索引版本机制重建/切换；旧索引继续可读，直到新索引校验通过。
5. 回滚时关闭多模态开关并切回旧索引别名；保留派生资源记录供再次启用复用，不在回滚路径删除内容中心对象。

## Open Questions

- kFile 当前是否提供按 `contentId` 删除内容及查询权威 MIME 的 SDK API；实现前需据此确定自动清理和回显响应字段。
- `qwen3.7-flash` 在目标兼容端点上的精确模型标识、图片大小/格式限制和 CDN 网络可达性需在集成环境确认。
- 首期图片过滤阈值、单文档图片上限及摘要最大长度需要以实际 PDF 样本压测后确定默认值。
- 外链图片允许域名采用全局 allowlist、知识库级 allowlist 还是“公网 HTTPS 默认允许 + denylist”，需结合部署网络策略确定；无论选择哪种，私网和元数据地址都必须拒绝。
