## Context

当前前端已经具备引用路由参数、`/citations/{chunkKey}` 解析、`locateChunk` 文本定位、持久 conversation store 和独立的 `ThinkingStream`，后端也已用 `source_document` 关联导入页与原附件。问题主要出在这些能力之间缺少稳定的渲染握手和明确的交互状态：引用定位在正文未完成异步挂载时可能执行，Custom Highlight API 没有完整的可见样式/兼容回退；页面 DTO 没有面向阅读器暴露来源预览信息；浮窗只承载当前会话；自动滚动只监听少量顶层值，不能准确表达用户是否仍在跟随底部。

本变更跨越 Wiki 页面 API、附件授权、文档预览和两个聊天视图。现有工作区有未归档变更与本能力相邻，因此实现必须复用 `source_document`、附件存储、会话 API、全局 store 和单一 SSE 所有权，不另建平行数据模型。

## Goals / Non-Goals

**Goals:**

- 让来自回答正文或参考列表的引用跳转最终落在正确页面、正确修订的可见文本上，并给出明显但临时的高亮。
- 允许有权用户在 PDF/DOCX 导入页内切换原文件和现有解析文本，预览全程保留授权边界并显示用户水印。
- 让浮窗内可直接创建、浏览和选择本人历史会话，同时保持完整页与浮窗共用状态和流连接。
- 用可测试的 follow-tail 状态机控制消息区和思考区滚动，并为展开折叠提供可访问动画。

**Non-Goals:**

- 不提供 OCR 校对、PDF/DOCX 在线编辑、源文件批注、格式转换或 DRM 级防复制能力。
- 不改变 Markdown 页面阅读方式，也不为手工创建的普通 Wiki 页伪造来源页签。
- 不展示模型隐藏推理、系统提示或未授权证据；“思考链”仍仅指服务端允许公开的执行摘要。
- 不重做会话持久化、分页协议或建立第二条 SSE；也不改变完整聊天页现有历史管理能力。

## Decisions

### 1. 引用导航采用“目标解析—页面就绪—定位—高亮”的一次性事务

点击参考项后继续使用稳定的 `childChunkKey` 导航。目标页面先加载并确认 `resourceId`/修订，再由 `PageReader` 自身的正文元素引用发出“内容已提交”信号；定位任务携带递增 token，页面或 chunk 改变时使旧任务失效。这样不会依赖全局 `document.querySelector`、固定延时或跨页面残留 watcher。

定位优先使用引用的精确 excerpt 和字符范围，在规范化空白后只接受唯一或与 `charStart` 最近且可验证的匹配；标题路径只能帮助缩小范围，不能在歧义时盲目高亮同名文本。成功后滚动到视口中部，通过 CSS Custom Highlight API 显示 `::highlight(kwiki-citation)`；不支持该 API 时用临时 `<mark>` 范围包装并在计时结束或页面切换时无损清理。路由中的 chunk 参数只在成功或已显示最终错误状态后消费，防止重渲染重复执行。

备选的“给整个段落加 class”无法表达跨文本节点范围且可能高亮过多；“只调用 scrollIntoView”也不能满足可确认的落点反馈，因此不采用。

### 2. 来源预览复用 `source_document`，通过授权端点提供短生命周期内容

页面详情增加可选 `sourceDocument` 摘要（来源格式、文件名、大小和预览能力），只在当前用户仍可读页面且来源附件有效时返回。预览内容通过页面作用域端点获取，服务端在每次请求时重新检查页面授权和附件关联，再返回受保护的流或短时签名 URL；永久 CDN URL 不进入页面正文、store 或持久缓存。现有 `source_document(page_id, attachment_id)` 足以表达关联，预期无需数据库迁移。

阅读器仅在来源格式为 PDF/DOCX 时显示两个页签，标签随格式为“PDF 源文件”或“DOCX 源文件”以及“解析文本”。PDF 使用基于 PDF.js 的本地预览适配器直接渲染原 PDF；DOCX 使用浏览器端 DOCX 预览适配器渲染原文件。二者先通过授权请求取得 Blob/Object URL，并在切页或卸载时撤销 URL、销毁渲染任务。选择本地渲染而非第三方在线转换服务，可避免把私有文档发送到新域名；组件封装统一加载、失败、重试和不支持状态。

预览容器叠加不可交互、重复铺设的水印层，内容至少包括当前用户名/用户 ID 和查看时间。水印覆盖滚动视口及打印样式，但它只承担泄漏溯源和视觉提醒，不宣称阻止截图或底层网络访问。`prefers-reduced-motion` 不影响水印可见性。

### 3. 浮窗历史是当前全局 conversation store 的受控子视图

`ConversationLauncher` 增加工具栏按钮和内部 panel 状态：新建会话调用既有 `newConversation()`；历史会话打开浮窗内列表，复用 store 的分页/加载、错误和空状态，选择后调用既有 `select(id)` 并回到消息视图。运行中的会话切换沿用 store 的现有保护：不得隐式取消、复制或重新订阅当前 run；若当前实现禁止运行时切换，按钮显示明确禁用/提示而不是丢失生成状态。

历史 panel 只展示本人有权获得的会话摘要，键盘焦点保持在浮窗内，Escape 先关闭历史 panel、再次操作才最小化浮窗。完整页和浮窗仍挂载同一 Pinia store，任何时刻只有 store 拥有流请求。

备选的“在浮窗里嵌入完整 ConversationPage”会重复挂载路由级生命周期和流副作用，因此不采用。

### 4. 自动滚动由底部距离与用户意图共同驱动

消息区和展开的思考区分别维护 `FOLLOWING`/`PAUSED` 状态。初始加载、新建或切换会话完成后定位到底部；生成期间仅在更新前仍距底部不超过 48px 时跟随。wheel、touch、PageUp/Home/方向键等用户上滚使区域离底后进入 `PAUSED`，此时 token、活动步骤、高度动画和图片加载均不能修改 `scrollTop`；用户滚动回阈值内立即恢复 `FOLLOWING`。

内容变化使用底部 sentinel 加 `ResizeObserver`/渲染后调度统一处理，而不是只 watch answer 字符串，因此历史加载、检索步骤、引用和思考摘要增长都遵守同一规则。外层消息区与思考区完全独立，内层滚动事件不得恢复或抢占外层跟随。

思考区保持折叠时只显示最新公开摘要，展开内容使用可测高度/网格行与 opacity 过渡，结束后回到 `auto` 高度以允许持续流入。动画期间只有处于 `FOLLOWING` 的区域才校正到底部；`prefers-reduced-motion: reduce` 时立即切换但保留全部状态和 ARIA 语义。

## Risks / Trade-offs

- [大型 PDF/DOCX 在浏览器渲染消耗内存或阻塞主线程] → 预览组件按需加载，PDF 分页/懒渲染，限制并提示超限文件，切换时主动销毁任务和 Object URL。
- [前端叠加水印可被有意规避] → 明确其为审计提醒而非 DRM；服务端仍以授权、短时 URL、禁止持久缓存为真正边界。
- [引用文本经 Markdown 渲染后空白或节点边界变化] → 使用规范化文本映射回 DOM Range，并要求唯一/邻近校验；失败显示引用 excerpt，不进行猜测高亮。
- [ResizeObserver 与动画造成滚动抖动或反馈循环] → 帧级合并更新，只在 `FOLLOWING` 时写 scrollTop，并用阈值和程序滚动标志区分用户意图。
- [运行中切换历史会话会混淆活动 run] → 会话切换完全委托 store 的单运行规则；UI 在不能安全切换时明确阻止，不创建额外连接。
- [新增预览依赖增大首包] → PDF/DOCX 适配器按页签动态导入，并单独拆包。

## Migration Plan

1. 先扩展页面来源 DTO 和授权预览端点，保持字段可选，旧前端不受影响；用 API 测试验证跨用户、跨页附件和失效来源均不可预览。
2. 引入懒加载预览适配器和水印层，再启用 PDF/DOCX 页签；Markdown 与无来源页作为回归基线。
3. 替换引用定位生命周期并补齐高亮样式/回退，保留现有 `chunk` 深链格式。
4. 在复用 store 的前提下增加浮窗历史 panel，最后接入统一 follow-tail 状态机和思考动画。
5. 通过组件测试和浏览器端到端测试后发布；若预览依赖出现问题，可关闭源文件页签而不回滚页面、聊天或数据。API 新字段/端点可向后兼容保留。

## Open Questions

无阻塞问题。实现阶段按已导入附件的实际 MIME 与签名校验决定 PDF/DOCX 适配器，不能仅信任文件扩展名。
